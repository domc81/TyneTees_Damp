## Section 2: Costing Events

### Flow

1. **Trigger:** Office/surveyor navigates to `/survey/[projectId]/costing`
2. **Process:**
   - Loads `survey_data` JSONB from `surveys` table
   - Mapping engine (`src/lib/survey-mapping.ts`) transforms room-by-room wizard data into `LineInput[]`
   - Pricing engine (`src/lib/pricing-engine.ts`) calculates costs using 8 formula types
   - Travel overhead (`src/lib/travel-overhead.ts`) appends labour + mileage cost
   - Returns: `CostSummary` — materials_total, labor_total, travel_cost, subtotal, vat_amount, total, deposit_30_percent
3. **Storage:** Result is **ephemeral** — not persisted until "Generate Quotation" is clicked
4. **Costing-to-Quotation:** Costing page shows "Generate Quotation" button → POST `/api/surveys/[id]/quotation` → creates `quotations` row (status=`draft`) and `quotation_sections` rows (frozen snapshot of all financial data at that moment)

**Who triggers it:** Office or surveyor (anyone with access to the survey)
**Who cares:** Office (to review costs before sending quote to customer)
**Notifications triggered:** None

| Status | Meaning |
|--------|---------|

| `generated` | AI narrative generated |
| `reviewed` | Staff reviewed and possibly edited |

**Source:** `src/types/survey-report.types.ts`, `survey_reports` table

### Report Status Transitions

| Event | Trigger | Function / File | Status Change | Who Cares |
|-------|---------|-----------------|---------------|-----------|
| Report created | Office navigates to report page | Page load — `src/app/survey/[projectId]/report/page.tsx` | → `draft` | Office |
| AI narrative generated | Click "Generate with AI" | POST `/api/generate-report` | → `generated` | Office |
| Sections edited inline | Manual edits on report page | `updateReport()` — `src/lib/report-data.ts` | → `reviewed` | Office |
| Report finalised | Click "Finalize" button | `updateReport(status='finalised')` | → `finalised` | Office, admin |
| Report published | Click "Publish" button | `publishReport()` — `src/lib/report-publish.ts:48–72` | → `published` + sets `publish_token` + sets `published_at` | Customer (needs to be notified) |
| Report unpublished | Click "Unpublish" | `unpublishReport()` | Clears `publish_token` — URL immediately stops working | |

### Public Report URL

- Pattern: `/report/{reportId}?token={publish_token}`
- Token: 64-char hex (122 bits entropy), generated by `generatePublishToken()`
- Access control: Token IS the credential — anyone with the URL can view
- **How currently shared:** Manual only — office copies URL and sends via external channel (email/phone/WhatsApp). No automated sending exists.

### Report View Tracking

**None.** Unlike quotations, the report page does NOT record visits. No `first_viewed_at`, `view_count`, or equivalent tracking table.

## Section 4: Quotation Lifecycle

### Database Tables

| Table | Purpose |
|-------|---------|
| `quotations` | Status, financial totals, share token, view tracking |
| `quotation_sections` | Per-section cost breakdown (frozen snapshot) |
| `quotation_views` | Per-view record: ip_address, user_agent, referrer, timestamp, duration |

### Quotation Status Enum Values

| Status | Meaning |
|--------|---------|
| `draft` | Created, not yet sent to customer |
| `sent` | Customer has been given the link (set manually) |
| `viewed` | Customer has opened the link (auto-transitions on first view) |
| `accepted` | Customer accepts — **NO UI BUTTON IMPLEMENTED** |
| `declined` | Customer declines — **NO UI BUTTON IMPLEMENTED** |

### Quotation Status Transitions

| Event | Trigger | Function / File | Status Change | Who Cares |
|-------|---------|-----------------|---------------|-----------|
| Quotation generated | Click "Generate Quotation" on costing page | POST `/api/surveys/[id]/quotation` | → `draft` | Office |
| Link sent to customer | Office manually copies URL | No API — manual action | `draft` → `sent` (manual update) | Office, customer |
| Customer opens URL | Customer loads `/q/[token]` | POST `/api/q/[token]/view` (fire-and-forget) | `sent` → `viewed` (auto on first view) | Office |
| Customer views again | Customer reloads page | POST `/api/q/[token]/view` | Increments `view_count`, updates `last_viewed_at` | Office |
| Customer accepts | **NOT IMPLEMENTED** | — | → `accepted` | Office, admin |
| Customer declines | **NOT IMPLEMENTED** | — | → `declined` | Office, admin |

### Share Token

- Stored in `quotations.share_token` (UUID-based, 122 bits entropy)
- Public URL: `/q/{share_token}`
- No expiry — valid until quotation is deleted or status manually changed

### Public Quotation Page (`/q/[token]`)

**Authentication:** Token-based — no login required, token in URL path

**What the customer can see:**
- Quotation document with professional formatting
- Customer name & address ("Prepared for" section)
- Site address
- Surveyor name & qualifications
- Cost breakdown: mandatory works, optional works, site prep, overheads
- Financial summary: subtotal, VAT, total, deposit, balance due
- Terms & conditions
- Surveyor notes
- Expiry warning if `valid_until` < today
- Company phone and email (clickable)

**What the customer can DO:**
1. View quotation (read-only HTML)
2. Download PDF — button triggers GET `/api/q/[token]/pdf`
3. Print (CSS `@media print` formatting applied)
4. Click phone → `tel:` link
5. Click email → `mailto:` link
6. **Cannot accept/decline** (no buttons)
7. **Cannot comment or message** (no system)
8. **Cannot pay deposit online** (no payment integration)

**Robots:** `{ index: false, follow: false }` — not indexed by search engines

## Key Findings

### What exists today
1. **In-app booking notifications** — surveyors receive real-time notifications for booking events via NotificationBell (Supabase Realtime). Works only when logged in.
2. **Quotation view tracking** — the platform records when customers open quotation URLs, updating `first_viewed_at`, `view_count`, and `quotation_views` table.
3. **Quotation expiry display** — customers see an expiry banner on the public page.
4. **Token-based public pages** — both quotations (`/q/[token]`) and reports (`/report/[id]?token=`) are accessible via secret URLs with no login required.

### What is completely absent
1. **Email sending** — no email provider integrated anywhere (no Resend, SendGrid, Nodemailer, etc.)
2. **SMS sending** — no SMS provider integrated (no Twilio, etc.)
3. **Customer notifications of any kind** — customers are never notified of anything automatically
4. **Surveyor email/SMS alerts** — surveyors only notified if actively logged into the app
5. **Booking reminders** — no scheduled jobs, no reminder infrastructure
6. **Customer accept/decline on quotations** — no UI, no API, no tracking
7. **Report view tracking** — unlike quotations, report views are never recorded
8. **Enquiry/survey status change notifications** — no notifications when status changes
9. **Communication history** — no audit trail of when the office contacted a customer

### Data available but unused for communication
- All customers have `email` (required field)
- All customers have `phone` (required field)
- Some customers have `mobile` (optional)
- All users/surveyors have `email` (required)
- Some users have `phone` (optional)
- `booking_reminder` notification type is defined in the type system but never triggered
- Customer contact snapshots are stored on `survey_bookings` (`customer_email`, `customer_phone`) — ready to use for booking communications
